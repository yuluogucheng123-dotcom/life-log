先说结论，省得你被吓到

这个 App 的数学难度 ≈ 初中水平。没有算法、没有微积分、没有线性代数。真正用到的只有：百分比、平均值、日期加减、集合去重。

第一级 · 必须懂不懂这些，代码根本写不出来

必须JavaScript 基础语法

这是唯一的核心语言，全项目 2000 行左右都是它。要掌握：

  • 变量与类型（const / let、字符串、数字、布尔、数组、对象）
  • 函数、箭头函数、参数与返回值
  • 条件与循环（if / for / for...of）
  • Map / Set 这两个数据结构 —— 去重、查表全靠它们
在哪里用到：全部文件。data.js、app.js、insight.js 全靠这些基础拼出来。

必须数组操作（最常用的一类）

数据处理 90% 的时间都在跟数组打交道。必须熟练：

  • filter 筛选、map 转换、reduce 归并求和
  • sort 排序、find 查找、some / every 判断
  • 对象展开 {...a, ...b}、数组展开 [...arr]
在哪里用到：insight.js 里「最大一笔」就是 reduce 逐个比大小；「按分类汇总」是 filter + reduce 组合。

必须异步编程 async / await

网络请求不是立刻返回的，代码要能「等」。这是新手最容易卡住的地方。

  • async 函数 + await 等待结果
  • Promise 是什么、「还没完成」这个状态怎么表示
  • try / catch 捕获失败 —— 网络随时会断
在哪里用到：sync.js 整个文件都是异步的：登录、上传、下载全部要等网络。

必须DOM 操作

DOM = 浏览器把 HTML 变成的一棵「元素树」。JS 通过它改变页面内容。

  • querySelector 选中元素、addEventListener 绑定点击
  • 改文字 textContent、改样式 classList
  • 事件委托：在父元素上监听，处理所有子元素的点击
在哪里用到：app.js 1035 行里大半在做这件事。删除按钮就是用事件委托，一个监听管所有记录。

必须HTML 与 CSS

页面长什么样、怎么排版，靠这两个。

  • HTML：标签结构、id / class / data-* 属性
  • CSS：选择器、盒模型、flex 布局
  • 响应式：media query 让同一套代码适配手机和电脑
  • 安全区域：env(safe-area-inset-*) 避开 iPhone 刘海和底部横条
在哪里用到：style.css 835 行、index.html 263 行。深色主题靠 CSS 变量统一管理。

必须数据持久化 localStorage

浏览器自带的小仓库，关掉页面数据还在。这是本 App「断网也能用」的基础。

  • localStorage.setItem / getItem 存取字符串
  • JSON.stringify / JSON.parse —— 对象和字符串互转，必会
  • 容量约 5MB、只能存字符串、清浏览数据会丢
在哪里用到：data.js 的读写函数、sync.js 的待同步队列，都存在这里。

第二级 · 最好懂不懂也能跑，但做不出「精致」的版本

重要HTTP 协议与状态码

前后端对话的语言。不要求背，但要能看懂「服务器在说什么」。

  • 请求方法：GET 取数据、POST 新建、PATCH 修改、DELETE 删除
  • 状态码：200 成功、201 创建成功、401 没登录、403 没权限、409 冲突、500 服务器出错
  • 请求头：Authorization: Bearer xxx —— 带上身份令牌才能访问数据
在哪里用到：我当时就是靠「POST 返回 201 但 upsert 返回 409」这个差异，定位到复合主键配置错误。

重要REST 与数据 API

一种「用网址表示数据」的风格。Supabase 自动把数据库变成了这样的接口。

  • 查询参数控制筛选、排序、返回哪些字段
  • upsert（有则更新、无则插入）与 主键冲突的关系
在哪里用到：sync.js 的 onConflict: 'id,user_id' 就是这里的关键 —— 冲突列必须和数据库实际主键完全一致。

重要身份认证与会话

「你是谁」这件事怎么证明，以及怎么记住你已登录。

  • 注册 / 登录 / 登出三种流程
  • Token（令牌）：登录成功后服务器发的凭证，后续请求都带着它
  • 会话持久化：关掉浏览器再打开还能免登录
在哪里用到：sync.js 的 signUp / signIn / getSession。autoRefreshToken 就是令牌过期自动续期。

重要数据库与 SQL 基础

数据在服务器上怎么存、怎么保证安全。

  • 表、行、列，主键（唯一标识一行）
  • 复合主键：用两列组合起来当唯一标识 primary key (id, user_id)
  • 索引：加速查询
  • 级联删除：on delete cascade 用户注销时数据跟着删
在哪里用到：supabase-schema.sql 82 行，建两张表。

重要RLS 行级安全 本 App 最关键的安全设计

这条不懂，你的 App 就是「任何人都能读所有人的数据」。它是数据库层面的强制隔离，不是前端藏起来。

create policy "own entries select"
on public.entries for select
using (auth.uid() = user_id);

翻译：「你只能读到 user_id 等于你自己的那些行。」这条规则对管理员本人也生效。

在哪里用到：supabase-schema.sql 第 40–76 行。因为有了它，这个 App 才敢公开给朋友用。

重要离线优先架构与冲突合并

一个设计思想：本地数据是唯一真相，云端只是备份和同步通道。

  • 改动先在本地生效 → 界面永远秒开、断网照常用
  • 失败的操作进队列，联网后自动补传
  • 软删除：不真删，只标记 deleted=true，否则多设备会互相「复活」数据
  • last-write-wins：按 updated_at 时间戳比较，谁晚听谁的
在哪里用到：sync.js 整个文件的设计主线，文件开头注释就写明了。

重要Service Worker 与 PWA

让网页变成「能装到手机桌面、能离线打开」的技术。

  • Service Worker：浏览器后台的一个代理，能拦截网络请求、返回缓存
  • 缓存策略：缓存优先 / 网络优先 / 两者折中
  • manifest：告诉系统应用名、图标、启动方式
  • 版本号与缓存更新：改了代码必须改缓存版本号，否则用户永远拿旧版
在哪里用到：sw.js 110 行、manifest.webmanifest。我在这里踩过最大的坑 —— 缓存没命中时返回了 undefined，导致首屏整个白屏。

第三级 · 数学真的不多，而且都是初中的

① 百分比 —— 用得最多的一个

算「比上期涨了多少」「预算用了百分之几」。

涨幅 = (本期 − 上期) ÷ 上期 × 100

要特别注意除数为 0 的情况 —— 上期没花钱时，百分比没有意义，必须单独判断（我代码里就写了 if (!prev) return null）。

② 平均值

日均支出、平均每次健身时长。

平均值 = 总和 ÷ 天数

③ 日期运算 最容易出隐蔽 bug 的地方

要理解三个概念：

  • 时区：UTC 和中国时间差 8 小时。用 toISOString() 在凌晨会把日期算成前一天
  • 月份从 0 开始：JS 里 getMonth() 一月返回 0，所以到处要 +1 / -1
  • 一周从周日开始：所以要手动推算「本周一」，见下面这段
// 求所在周的周一
const day = d.getDay(); // 0=周日
const diff = day === 0 ? -6 : 1 - day;
在哪里用到：data.js 的日期工具函数。我特意没用 toISOString，就是躲时区坑。

④ 集合去重与计数

「本期有多少天在学习」—— 同一天记三笔只能算一天。

new Set(list.map(e => e.date)).size

Set 会自动去掉重复值。这是离散数学里「集合」概念的直接应用，但用起来就一行。

⑤ 连续天数算法 本 App 唯一的「算法」

就是「连续打卡多少天」。做法很朴素：

  • 把所有日期排序，从今天往回数，能连上就 +1，断了就停
  • 最长纪录：遍历一遍排序后的日期，看相邻两天是不是差 1 天

复杂度是 O(n log n) —— 排序造成。但对个人数据（几百条）完全无感。

⑥ 你不需要的数学

微积分、线性代数、概率统计、图论、数值分析 —— 一个都没用到。如果要做数据图表（趋势线、饼图圆心角、坐标映射），会用到一点三角函数和线性映射，但也只是套公式。

第四级 · 网络协议你问的这块，单独说清楚

了解HTTPS / TLS

你看到的所有网址前面的 https://。含义是「这条通信被加密了」，中间人看不到内容。

为什么必须：GitHub Pages 和 Supabase 强制 HTTPS。PWA 也必须在 HTTPS 下才能安装到桌面（localhost 例外）——因为 Service Worker 权限太大，不加密不敢给。

了解DNS 与域名

把 yuluogucheng123-dotcom.github.io 这种人类可读的名字，翻译成服务器 IP 地址。

为什么和你的 App 有关：你说过 supabase.com 能开、supabase.co 不能 —— 这就是 DNS 解析或网络封锁层面的问题，不是代码问题。VPN 能解决，因为它改的是解析和路由路径。

了解CORS 跨域

浏览器的安全机制：一个网站默认不能随便访问另一个网站的接口，除非对方明确允许。

为什么和你的 App 有关：你的页面在 github.io，数据在 supabase.co —— 这是两个不同的域。Supabase 默认允许跨域访问，所以能直接用。如果你以后自建后端，就必须配置 CORS，否则请求会被浏览器拦掉。

了解WebSocket

和 HTTP 不同，它建立连接后可以双向持续通信，适合实时推送。

为什么和你的 App 有关：我当时写自动化测试，就是用 Node 手写了一个极简 WebSocket 客户端去控制无头 Edge 浏览器（CDP 协议走的就是 WebSocket）。不用自己实现协议，但要知道它和 HTTP 的区别 —— HTTP 是你问一次它答一次，WebSocket 是接通后双方随时能说话。

了解Token 认证 vs Cookie

两种「证明你已登录」的常见方式。Supabase 用的是 JWT Token：

  • 登录成功后服务器发一串加密字符串（令牌）
  • 之后每次请求都放在 Authorization 头里带着
  • 令牌有有效期，过期要用 refresh token 换新的

publishable 密钥为什么能公开：因为它只是「项目门牌号」，真正的权限由 RLS 和用户令牌决定。而 service_role 密钥能绕过所有 RLS，所以绝对不能泄露。

网络协议这块的实际结论

做这个 App，你不需要背协议细节，但需要建立三个直觉：

1. 数据在网络上来回跑，随时可能失败 → 所以代码必须处理失败（离线队列）。
2. 浏览器有安全边界（HTTPS、CORS、同源策略）→ 所以有些事必须在服务器做。
3. 身份靠令牌证明，权限靠服务端强制 → 所以前端藏起来的按钮不叫安全，数据库拦截才叫安全。

第五级 · 工程实践不会这些，代码写出来是坏的，但你看不出来

重要调试能力 比写代码更值钱

  • 浏览器开发者工具：Console 看报错、Network 看请求、Application 看存储
  • 看懂报错堆栈：文件:行号 + 错误类型
  • 二分定位法：不确定哪出错，就一段段注释掉试

这项目三个致命 bug，没有一个是靠读代码发现的，全是靠实际跑 + 看请求 + 看返回值定位的。

重要自动化测试 CDP

让程序自己去点按钮、填表单、验结果。我用的是 Chrome DevTools Protocol（CDP）直接控制无头浏览器。

为什么关键：静态检查（语法）能发现「代码写错了」，但发现不了「代码写对了、逻辑是错的」。比如「上传返回 409」这种事，只有真的发一次请求才知道。

了解版本控制 Git

  • git init / add / commit / push 四个命令覆盖 90% 场景
  • 理解「提交」= 给代码存一个档，可以随时回退
  • .gitignore 排除不需要上传的文件

了解部署与静态托管

GitHub Pages 把你仓库里的文件变成公开网站。关键认知：这个 App 没有传统后端服务器 —— 它是一堆静态文件 + 一个第三方数据库服务。这种架构叫 Serverless（无服务器）。

了解命令行 / Shell

用打字代替点击来操作电脑。这个项目用 PowerShell（Windows 上）。

需要会到什么程度：能看懂 cd、ls、node xxx.js 就行。真正写代码我用的是编辑器，不是命令行。

如果要从零开始学按这个顺序，别跳

第 1 阶段：静态页面（1–2 周）
  • HTML 标签 + CSS 选择器 + flex 布局
  • 目标：能照着做出「今天」那个页面的样子（先不管功能）
  • 关键：不要背标签，用到再查。理解「盒子模型」比记住属性重要

  • 目标：点按钮能加一条记录，并显示在列表里
  • 关键：这个阶段最痛苦，因为要同时理解语法和浏览器。熬过去就好了

  • JSON、localStorage、数组的 filter/map/reduce
  • 目标：刷新页面数据还在，周报能算出来
  • 关键：把数据操作练熟，这部分占了实际工作量的 40%

  • PWA / Service Worker、Git、GitHub Pages
  • 目标：手机能装到桌面、离线能用、有网址能分享
